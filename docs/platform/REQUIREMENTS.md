## 1. Legend

- **REQ-ID**: one buildable requirement (`REQ-<MODULE>-<nn>`); task cards live at `docs/platform/tasks/<REQ-ID>.md`; commits and PRs name a REQ-ID or an R-id.
- **Priority**: MUST / SHOULD / COULD (MoSCoW) for the release in the Release column.
- **Phase**: build phase 1–8 in which the row is completed; `R2`/`R3` = not built in this build (DEFERRED with an ADR). For an R-id row (§2) the Phase is the latest phase among its Release-1 REQ-IDs and the clauses of its ACs, i.e. the phase at which the R-id can become DONE; the check script recomputes it and fails on drift.
- **Release**: R1 (this build, before G8), R2, R3 (`docs/spec/11`, ADR-008). Nothing is dropped, only scheduled.
- **Status**: TODO · IN-PROGRESS · DONE (every linked AC test passes in CI on the integration branch) · DEFERRED (needs an ADR number) · NEEDS-HUMAN (needs a `DECISIONS-NEEDED.md` entry).
- **AC clauses**: an AC whose clauses land in different phases is split into `AC-X/a`, `AC-X/b`; the clause text says which part it asserts. The full AC passes when every clause passes.
- **Code paths** are planned (`backend/src/bridge/…` = `bridge/…`; `frontend/app/…`); they are corrected as code lands.
