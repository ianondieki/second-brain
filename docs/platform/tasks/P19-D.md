# P19-D · Editor trust checks: originality (REQ-PROP-04) and over-disclosure (REQ-REPO-01, warn only)

Agent: impl-ai (high). Worktree. No schema change (`proposal_lsh_bands`, `originality_checks`, `OriginalityBand`
and the two `models.yaml` tasks `originality_explainer` and `over_disclosure_check` exist). Map: scratchpad
`p19/map-editor-checks.md`. Spec: `docs/spec/06` §6.1 (over-disclosure), §6.3 (originality), `docs/spec/09`.

## Scope

1. **`proposals/originality.py`.** Plain-Python MinHash (no new dependency, D-36): 5-word shingles over the
   submitter's Tier-1 text (`TIER1_FIELDS` through `sanitise.plain_text`), 128 hashes (blake2b with fixed salts),
   16 bands × 8 rows into `proposal_lsh_bands` at publish (`service.publish`, next to `_PUBLISH`), plus the teaser
   embedding through the configured `Embedder` (`embedder_from_settings`; the fake in tests and the demo). The check
   compares the current draft text against **other owners'** published, clear teasers only: candidates from the LSH
   buckets, Jaccard on the shingle sets (≥ 0.8 → high), and cosine on the embedding (≥ 0.88 → high; between 0.75 and
   0.88 → some) with the thresholds in `policy.yaml` `originality:` (strict loader like `assistant_policy.py`). The
   answer is a band only (`none | some_overlap | high_overlap`), with `compared: int` (how many teasers were in the
   pool, never which) and an optional explainer sentence from the `originality_explainer` task, which sees the
   submitter's Tier-1 text and the matched teasers' Tier-1 text only, with the D-37 demo-data rule and the labelled
   demo fallback (`DemoFallbackFlag`). Never any Tier-2 field: `guard.check_tier2` and
   `test_no_tier2_in_llm_calls.py` cover the task; the response schema has no field that could carry another
   owner's text beyond the one sentence, and the sentence is checked not to contain any matched teaser's shingles
   verbatim (copy `copies_tier2`'s shingle check).
2. **Limit.** ≤ 10 per developer per Nairobi day, counted on `originality_checks` (one row per check with the band),
   429 `originality_limit` after; an in-flight guard per proposal like the assistant's `InFlight`.
3. **Endpoint.** `POST /api/me/proposals/{proposal_id}/originality` (owner only, draft or published; not behind the
   Tier-2 gate), response `{band, compared, explanation: str | None, demo_fallback: bool, checked_at}`;
   `GET …/originality` returns the last check of the day for this proposal (so the editor can show it again).
4. **Over-disclosure.** `proposals/disclosure.py`: task `over_disclosure_check` (Haiku in `models.yaml`, Tier-1
   only, the same consent purpose and demo-data rule as the assistant) returns `{flagged: bool, fields: list[str],
   why: str}` for the teaser; a deterministic pre-check runs first and short-circuits the LLM when it already finds
   the obvious ("algorithm", "architecture", "we use", code fences, library names in the summary): so the fake
   provider still gives a useful demo answer. Endpoint `POST /api/me/proposals/{proposal_id}/disclosure-check`
   (owner only, draft), 10 per day on the same counter table? No: it is an LLM task, so the assistant's daily
   `llm_calls` limit covers it (same `check_daily_limit`). Warn only: nothing blocks publishing.
5. **Policy.** `policy.yaml` `originality: {jaccard_high: 0.8, cosine_high: 0.88, cosine_some: 0.75, daily_limit: 10}`.

## Decisions taken (impl-ai, 2026-10-02)

The thinnest honest option where the card left a choice:

1. **Where GET finds the last check.** `originality_checks` has no `proposal_id` (no schema change), so the check
   writes a `proposal.originality_checked` audit event (payload: version, band, `compared`, `demo_fallback`, the
   explainer's reason code, trace id, `checked_at`; the sentence goes to `event_details`, the mutable part). GET reads
   the caller's own latest event for the proposal and answers `null` when it is not from today (Nairobi day).
2. **403 or 404.** 403 `not_owner` for a proposal the caller can see but does not own (another owner's published
   teaser), 404 when it is invisible (another owner's draft, unknown id), 409 `proposal_hidden` once deleted. The
   disclosure check uses the same rule.
3. **Which text.** Both checks read the saved draft version when there is one, else the current version (a
   published proposal is edited through a new draft), and only its four Tier-1 columns; no text comes in the body.
4. **No per-session opt-in.** Neither check asks for the assistant's `tier2_llm_assistant` opt-in: both send Tier-1
   text only (docs/spec/09 ground rules; `models.yaml` purpose `tier1_only`, like `moderation_prescreen`). The D-37
   demo-data rule applies through the routed client exactly as for the assistant. See the open question below.
5. **Matches and the explainer.** Jaccard matches (≥ `jaccard_high`) rank above embedding matches (≥ `cosine_some`);
   at most `max_explained` (3) go to the explainer, which is not called for `none`. There is no "some" Jaccard
   threshold (the spec names none), so with the fake embedder only near-copies show an overlap in the demo.
6. **What code accepts from the explainer.** One plain sentence of at most `explanation_max_chars`, rejected when it
   has any digit (no score, share or count slips through), contact details, or a 5-word run of any matched teaser's
   Tier-1 text. A refused or failed explainer call never fails the check: the band stands without a sentence.
7. **Caps in YAML, index format in code.** `policy.yaml` `originality` also holds `max_candidates` (200),
   `max_explained` (3) and `explanation_max_chars` (300). The MinHash shape (5-word shingles, 128 hashes, 16 × 8, the
   salts) stays in code: it is the stored index format, and a change needs a re-index.
8. **Embeddings.** Only vectors of the embedder's own `embed_model` and `embed_version` are compared. When the
   embedder cannot run (`EmbedderUnavailable`) the check uses Jaccard only and publish clears the stale vector. The
   embedder is built lazily on `app.state` (`EmbedderDep`).
9. **Limit.** A per-user advisory transaction lock serialises today's count with the new row; `created_at` is written
   from `clock.utcnow()` so the test clock applies. The in-flight guard is per proposal (one at a time).
10. **Disclosure limit.** The assistant's `max_calls_per_user_day` applies to this task's own `llm_calls` rows (the
    same number, a separate count), 429 `disclosure_rate_limited`; one call per user at a time (429
    `disclosure_busy`). Refusals reuse `assistant.refusal` (its `assistant_*` codes and wording).
11. **Response extras.** `OriginalityOut` adds `ai_drafted`; `DisclosureCheckOut` is `{flagged, fields, why, source
    (rules | model | none), ai_drafted, demo_fallback, version_id}`.

Left out: a backfill of bands and embeddings for teasers published before this change (the demo seed publishes
through the API, so a fresh seed is indexed); `bridge/jobs/tier2_similarity.py` (not P19); the docs/spec/09
originality eval set; the editor UI (P19-F).

Open question for the orchestrator: the card says the over-disclosure task uses "the same consent purpose ... as the
assistant". Read literally that is the per-session `tier2_llm_assistant` opt-in; decision 4 does not require it
because only Tier-1 text is sent. If the opt-in is wanted, it is one `assistant.require_consent` line before the
model call (the rules answer would stay free of it).
