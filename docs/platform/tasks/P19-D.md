# P19-D · Editor trust checks: originality (REQ-PROP-04) and over-disclosure (REQ-REPO-01, warn only)

Agent: impl-ai (high). Worktree. No schema change (`proposal_lsh_bands`, `originality_checks`, `OriginalityBand`
and the two `models.yaml` tasks `originality_explainer` and `over_disclosure_check` exist). Map: scratchpad
`p19/map-editor-checks.md`. Spec: `docs/spec/06` §6.1 (over-disclosure), §6.3 (originality), `docs/spec/09`.

## Scope

1. **`proposals/originality.py`.** Plain-Python MinHash (no new dependency, D-36): 5-word shingles over the
   submitter's Tier-1 text (`TIER1_FIELDS` through `sanitise.plain_text`), 128 hashes (blake2b with fixed salts),
   16 bands × 8 rows into `proposal_lsh_bands` at publish (`service.publish`, next to `_PUBLISH`), plus the teaser
   embedding through the configured `Embedder` (`embedder_from_settings`; the fake in tests and the demo). The check
   compares the current draft text against **other owners'** published, clear teasers only: candidates from the LSH
   buckets, Jaccard on the shingle sets (≥ 0.8 → high), and cosine on the embedding (≥ 0.88 → high; between 0.75 and
   0.88 → some) with the thresholds in `policy.yaml` `originality:` (strict loader like `assistant_policy.py`). The
   answer is a band only (`none | some_overlap | high_overlap`), with `compared: int` (how many teasers were in the
   pool, never which) and an optional explainer sentence from the `originality_explainer` task, which sees the
   submitter's Tier-1 text and the matched teasers' Tier-1 text only, with the D-37 demo-data rule and the labelled
   demo fallback (`DemoFallbackFlag`). Never any Tier-2 field: `guard.check_tier2` and
   `test_no_tier2_in_llm_calls.py` cover the task; the response schema has no field that could carry another
   owner's text beyond the one sentence, and the sentence is checked not to contain any matched teaser's shingles
   verbatim (copy `copies_tier2`'s shingle check).
2. **Limit.** ≤ 10 per developer per Nairobi day, counted on `originality_checks` (one row per check with the band),
   429 `originality_limit` after; an in-flight guard per proposal like the assistant's `InFlight`.
3. **Endpoint.** `POST /api/me/proposals/{proposal_id}/originality` (owner only, draft or published; not behind the
   Tier-2 gate), response `{band, compared, explanation: str | None, demo_fallback: bool, checked_at}`;
   `GET …/originality` returns the last check of the day for this proposal (so the editor can show it again).
4. **Over-disclosure.** `proposals/disclosure.py`: task `over_disclosure_check` (Haiku in `models.yaml`, Tier-1
   only, the same consent purpose and demo-data rule as the assistant) returns `{flagged: bool, fields: list[str],
   why: str}` for the teaser; a deterministic pre-check runs first and short-circuits the LLM when it already finds
   the obvious ("algorithm", "architecture", "we use", code fences, library names in the summary): so the fake
   provider still gives a useful demo answer. Endpoint `POST /api/me/proposals/{proposal_id}/disclosure-check`
   (owner only, draft), 10 per day on the same counter table? No: it is an LLM task, so the assistant's daily
   `llm_calls` limit covers it (same `check_daily_limit`). Warn only: nothing blocks publishing.
5. **Policy.** `policy.yaml` `originality: {jaccard_high: 0.8, cosine_high: 0.88, cosine_some: 0.75, daily_limit: 10}`.

  candidate; a published teaser of the same owner is excluded; the bands at the thresholds (0.79/0.80, 0.87/0.88);
  a draft with no published teasers in the pool is `none` with `compared=0`.
