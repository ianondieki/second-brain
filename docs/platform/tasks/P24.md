# P24 — "Jacaranda in print": the seductive landing, a living Home, Explore, share cards (the owner's brief, 2026-10-07)

The owner: "I want a world class UI and user experience that is seductive … copy the design skills there [the three
references] … add more relevant features like a real full-stack engineer … make it dynamic rather than static, some
sections moving and showing life … cute images from the internet where relevant … /impeccable for polishing,
/frontend-design for designing, Playwright for responsiveness … do not stop until the design is up to the standards."
Direction: D-66. Authority order: CLAUDE.md, docs/spec/07, spec 04 §4.6 (simple UI), D-66, this card, then the skills.

## Acceptance (what "up to the standards" means here, measurable)

1. The ux-reviewer and the reviewer PASS; the owner's own look at the screenshot set is the final word.
2. Lighthouse (mobile default, Slow 4G) on `/`, `/explore`, `/dev`: performance ≥ 90 and accessibility ≥ 90, light and
   dark; LCP ≤ 2.5 s on `/` with the photographs in (D-53's band is not a licence to regress).
3. Every route ≤ 150,000 B gzipped JS; axe strict 0 at 360 and 1440, light and dark; one `[data-primary]` per screen;
   ≤ 2 chips per card; 44 px targets; no sideways scroll at 360; reduced motion respected everywhere something moves.
4. No fabricated figure, testimonial, logo or claim: stats are product constants or seeded figures labelled "Seeded
   example"; photographs are licensed and credited; copy changes tagged `[[COPY-REVIEW]]`/`[[SW-REVIEW]]` with en/sw parity.
5. The full Playwright suite, the clock scenarios and the demo story stay green; CI as the standing exceptions.

## Iteration

Bounded passes, not an open loop: build → batched review (reviewer, ux-reviewer, the orchestrator's own look at the
shots) → one fix round → confirmation → gate. A second design pass only if the confirmation still finds a MAJOR or the
owner asks for a change after seeing the screenshots.
