## The goal

By the end of P28: one container image runs the whole seeded product on one port on any Docker host, in a public-demo
mode where a visitor picks a persona and is signed in with one press, cannot lock other visitors out, cannot upload
files or move the shared clock, sees that the data is fictional and resets nightly, and is not indexed by search
engines; the owner can start a public link from GitHub Codespaces at zero spend in a few minutes, and has a ready
workflow and runbook for a durable host once D-71 is decided. Alongside it, the feature tracks below.

## Track PD — the public demo (REQ-FND-03; D-71)

**Why not simply put it online.** A durable public link needs a host. The research note
(`docs/platform/research/public-demo-hosting.md`, read 2026-10-13) found no host that runs a ~1 GB container durably at
zero spend without a card: Hugging Face Docker Spaces now need PRO (USD 9/month), Fly.io has no free tier, Render and
Koyeb free tiers have 512 MB, Oracle Always Free fits but needs a card for verification. GitHub Codespaces is free on
the owner's existing account but serves only while the codespace runs (idle timeout at most 4 h). Choosing between
spend, a card and an on-demand link is the owner's (CLAUDE.md: any spend or new vendor; D-36), and two open legal
decisions block "any hosted release": D-38 (news excerpts) and D-39 (legal drafts). So this track builds everything that
needs no decision, makes the public mode conservative by default, and records D-71 for the go-live.

**What a visitor sees.**
- `/login` (and the landing's main call to action) offers "Try the demo as…": six personas, each a card with name,
  role and one button — Amina Wanjiru (developer, D2), Brian Otieno (developer, D1), Grace Mwangi (Telco A, owner and
  admin), Peter Kamau (Telco A, signatory), Rita Njeri (Telco A, reviewer), Staff Moderator (platform staff). One press
  signs in and lands on that persona's Home. The email form stays below, folded ("Sign in with an account").
- A slim banner on every page: "Public demo: every name and organisation here is fictional, and the data resets every
  night at 03:00 EAT. Please don't enter real personal information." `[[COPY-REVIEW]]`, en and sw. Dismissible for
  the session; never covers content at 360 px.
- The user menu's sign-out reads "Switch persona" and returns to the persona picker.
- Locked in the public demo (each shows one calm line "Switched off in the public demo" where its form would be, and
  the API refuses): sign-up, magic link, password change, TOTP enrol/disable/recovery codes, OAuth sign-in and linking,
  email change, account deletion and data export, organisation membership changes (invite, remove, role change),
  every file upload (proposal attachments, message attachments, any other multipart route), the dev/test clock.
  Everything else works and is wiped at the nightly reset.
- Pages carry `noindex, nofollow` (header and `robots.txt` disallow-all).

**Content scope (conservative by default, the owner can widen it after the decisions).** In public mode the seed loads
only fictional organisations (the four fixtures) and only official-source research excerpts (`source_type: official`,
6 of 19); the provisional directory of real organisations (`ke_provisional.yaml`, 85 rows, "awaits an official citation
before G6") and the 13 news excerpts (D-38) are left out. `PUBLIC_DEMO_CONTENT=full` restores both once the owner has
decided D-38 and G6's citations; the runbook says so. Legal templates stay labelled as drafts (D-39).

**Contract.**
- Settings: `PUBLIC_DEMO: bool = False`; `PUBLIC_DEMO_CONTENT: Literal["fictional", "full"] = "fictional"`. Start-up
  refuses `PUBLIC_DEMO=true` unless `APP_ENV` is dev or test (`DEMO_ENVS`): fail closed, so a production or staging
  process never runs it. The persona router lives in `bridge/demo/` (absent from production images, like the test clock)
  and is mounted only when the module exists and `PUBLIC_DEMO` is true.
- `GET /api/public/demo` (always present, unauthenticated, cacheable 60 s) →
  `{enabled: bool, personas: [{key, name, role: "developer"|"org_admin"|"org_signatory"|"org_reviewer"|"staff",
  detail, home}], reset_hour_eat: 3|null}`; `{enabled: false, personas: [], reset_hour_eat: null}` when off.
- `POST /api/auth/demo/sign-in {persona}` (CSRF as every POST; throttled per IP with the existing throttle, 30 a
  minute) → `SessionResponse` and the session cookie; the session is created with `mfa_pending=false` and
  `mfa_verified_at=now` (so step-up actions work for the persona for ADR-002's 12 h), only for an `ACTIVE` user whose
  `demo_account` is true and whose address is one of the six (a fixed allowlist in code, not the request); audited as
  `auth.login` with `method: "demo_persona"`. 404 when the mode is off or the module absent; 400 `unknown_persona`.
- Locked routes answer 403 `{"detail": {"code": "public_demo_locked", "message": "This is switched off in the public
  demo."}}` when `PUBLIC_DEMO` is true; one dependency, applied by route, with a test that walks the app's routes and
  fails if a multipart route is not locked.
- The API adds `X-Robots-Tag: noindex, nofollow` when the mode is on; the web reads `PUBLIC_DEMO` at run time (server
  side, never inlined) for its header, `robots.txt` and the banner, and asks `/api/public/demo` for the personas.

**The image and the links (infra; no secrets in the repository).**
- `infra/demo/space/`: one Dockerfile (multi-stage: the backend venv with dev tools, the Next standalone build with
  `API_ORIGIN=http://127.0.0.1:8000`, PostgreSQL 16 with pgvector from the PGDG apt repository, the SeaweedFS and
  Mailpit binaries copied from their pinned images, Node 22's binary) and a standard-library Python supervisor
  (`run.py`) that, as uid 1000: generates throwaway secrets at each boot (the same generators as `infra/demo/demo.py`),
  initialises Postgres with the roles from `infra/postgres/`, starts SeaweedFS and Mailpit (internal only), runs the
  migrate and demo-seed steps with `PUBLIC_DEMO=true`, starts the api, the worker and the web on `PORT` (default
  7860), restarts a crashed child, and at 03:00 EAT stops the children, wipes the data directories and boots again
  (the nightly reset). Builds for amd64 and arm64 (Oracle's Ampere).
- `.github/workflows/demo-image.yml`: builds the image and pushes `ghcr.io/<owner>/bridge-demo:latest` (and the commit
  SHA) with the workflow's own `GITHUB_TOKEN` (`packages: write`); on dispatch and on pushes to the integration branch
  that touch the product; arm64 on dispatch only. No external secret.
- `.devcontainer/devcontainer.json`: a codespace built from that image (or from the Dockerfile when the image is not
  public yet) that starts the supervisor and forwards the port; `postAttachCommand` makes the port public with
  `gh codespace ports visibility` and prints the URL; the runbook gives the one-click fallback in the Ports tab.
- `.github/workflows/demo-space.yml` (dispatch only): pushes a two-file Space (`Dockerfile` = `FROM` the GHCR image,
  `README.md` with `sdk: docker`, `app_port: 7860`) to the Space named by the repository variable `HF_SPACE` with the
  secret `HF_TOKEN`; skipped with a notice when either is missing.
- `docs/runbooks/public-demo.md`: the owner's steps for Codespaces (now, zero spend), Hugging Face (after D-71 (a)),
  an Oracle Always Free VM with Caddy and an `sslip.io` name (after D-71 (b)), and the go-live checklist (D-38, D-39,
  G6 citations, `PUBLIC_DEMO_CONTENT`).

**Acceptance tests.**
- AT-PD-1 With `PUBLIC_DEMO=true`, `POST /api/auth/demo/sign-in {"persona": "amina"}` returns 200 and a session whose
  `/api/auth/me` is Amina's with MFA satisfied; an Express interest needing step-up succeeds without a code.
- AT-PD-2 With the mode off (or `APP_ENV=production` at start-up, which refuses), the sign-in route is 404 and
  `/api/public/demo` says `enabled: false`; a production image has no `bridge/demo` module.
- AT-PD-3 An unknown persona or a non-demo account's address is 400; a body naming an email is ignored.
- AT-PD-4 With the mode on, each locked route answers 403 `public_demo_locked`; the route walk finds every multipart
  route locked; a password change for a persona is refused.
- AT-PD-5 The public seed contains no `ke_provisional` organisation and no `news` excerpt; `full` restores both.
- AT-PD-6 (e2e, public project) `/login` shows six personas; pressing Grace lands on `/org`; the banner shows and
  dismisses; Settings › Security shows the locked line; `robots.txt` disallows all; axe strict 0 at 360 and 1440.
- AT-PD-7 (image) `docker run -p 7860:7860` serves `/` within the start-up budget, the persona flow works end to end,
  and a forced reset brings back the seeded state.
