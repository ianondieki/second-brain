## Build

1. **One error shape.** The API's shape is `bridge.errors.ApiError` → `{"detail": {"code", "message", …}}` (FastAPI's
   422 validation list is the one documented exception). Find every response that departs from it (ad hoc
   `JSONResponse`, `HTTPException` with a string detail, handlers returning other bodies, missing `ERROR_RESPONSES` on
   routers) and align it; a test that walks `openapi.json` and asserts every 4xx response of every route references
   `ApiErrorBody` (or is the 422), plus a test per fixed route.
2. **One pagination style.** List what list endpoints use (cursor `limit` + `cursor`/`next_cursor`, or anything else)
   and align the outliers on the dominant style without breaking callers. Record the table on this card.
3. **The moderation case page** (`tasks/P16-C2.md`, carried MINOR 4; found on the long-lived demo with 431 open cases):
   the frontend finds a case only in the 200-row queue list. Add `GET` of one case by id to the admin moderation API
   (same staff gates and 404 rules as the queue; `bridge/admin/deps.py`), switch `app/(admin)/admin/moderation/data.ts`
   `getCase` to it, with backend and frontend tests (a case beyond the first 200 opens).
4. **Consistent naming.** Route paths, query parameters and JSON fields: one case (snake_case in JSON), plural
   collections, the same noun for the same thing across modules. Fix only true inconsistencies, each with its frontend
   caller; list what you left and why.
5. **N+1 and slow paths.** For the main list and detail endpoints (developer: ideas list, idea, discover problems and
   projects, recommendations, companies, engagements list, tracker; organisation: inbox, matches, engagements list,
   tracker; staff: moderation queue, claims, research queue), add a query-count test (a SQLAlchemy `before_cursor_execute`
   counter, or the existing helper if one exists) with realistic data (e.g. 20 rows) asserting the count does not grow
   with the number of rows. Fix every N+1 in code (joins, `selectinload`, one batched query); no new indexes (write the
   need under "0006 needs").
6. **Logs and errors carry no personal data or secrets.** Audit every `logger`/`structlog` call and exception message
   that can reach a log or a response: no email addresses, phone numbers, names, free text from users, tokens, keys,
   passwords, TOTP codes, recovery codes, Tier-2 content, full URLs with tokens. The existing redaction tests
   (`tests/unit/test_logging.py`, `test_job_log_redaction.py`) stay; add tests for what you fix.
7. **Hermetic tests.** `bridge.config.Settings` reads `backend/.env` from an absolute path (`config.py:98`), and

   `backend/.env` copied from `.env.example` in place.
